# 🛠 Technical Implementation Guide: CryptoTrack

This document is intended for developers and technical reviewers. It outlines the architectural decisions, performance strategies, and logic implementations behind the CryptoTrack dashboard.

---

## 1. Architectural Pattern: Decoupled Logic (Custom Hooks)

The application follows a strict separation of concerns. UI components are primarily presentational, while all business logic, state orchestration, and side effects are encapsulated in **Custom Hooks**.

| Hook | Responsibility |
| :--- | :--- |
| **`useCryptoData`** | Manages API lifecycle, auto-polling (60s), countdown timers, and price change detection (flash state). |
| **`usePortfolio`** | Computes live P&L, total cost basis, and manages `localStorage` persistence for holdings. |
| **`useWatchlist`** | Manages a `Set` of coin IDs with `localStorage` sync for rapid favorites tracking. |
| **`useSort`** | Implements a memoized sorting engine for multi-column table sorting without re-fetching data. |
| **`useToast`** | A lightweight singleton-like state for managing a queue of notification objects. |

## 2. Performance Engineering

To maintain 60fps performance and avoid "jank" during mass data updates:

### A. Memoization Strategy
- **`React.memo`**: Applied to granular components like `CoinRow` and `CoinCard`. These components use a shallow comparison of props.
- **`useCallback`**: All event handlers passed to children are wrapped in `useCallback` to prevent breaking the `React.memo` optimization in child components.
- **`useMemo`**: Used for filtering the 50+ coin list and calculating portfolio stats. This ensures these calculations only run when the dependency (search query or price data) actually changes.

### B. Efficient Price Flash Detection
Instead of re-rendering every row on every refresh, the `useCryptoData` hook maintains a `prevCoinsRef`. On each fetch:
1. It compares `current_price` against the ref.
2. It identifies only the IDs that changed.
3. It sets a `flashIds` state which is passed down to only the affected rows.

## 3. Advanced Feature Logic

### 📊 Market Sentiment Calculation
The sentiment score is a weighted index. 
- **Formula**: `(Sum of Market Cap of Bullish Coins / Total Market Cap of Top 50) * 100`.
- **Implementation**: Bullish coins are defined as `price_change_percentage_24h > 0`. This provides a more accurate "market mood" than a simple count, as it reflects where the actual capital is moving.

### 💼 Portfolio P&L Engine
The portfolio system uses a **real-time valuation model**:
- **Total Value**: `Σ (holding.amount * coin.current_price)`
- **Cost Basis**: `Σ (holding.amount * holding.buyPrice)`
- **Unrealized P&L**: `Total Value - Cost Basis`
This calculation is memoized and re-triggers only when the underlying market data refreshes.

### 📐 SVG Mathematics (Gauges & Sparklines)
To keep the bundle size small, no heavy charting libraries (like Chart.js or Recharts) were used.
- **Gauge**: Uses basic trigonometry (`sin`/`cos`) to calculate the needle's `(x2, y2)` endpoints on a 180-degree arc.
- **Sparklines**: Uses SVG `<path>` elements where the `d` attribute is generated by mapping price points to a coordinate system `(x = index, y = price_ratio)`.

## 4. API Integration & Resilience

### A. Axios Configuration
Located in `services/cryptoApi.js`, the instance includes:
- **15s Timeout**: Prevents "hanging" requests on poor connections.
- **Rate Limit Handling**: CoinGecko's free tier is prone to `429 Too Many Requests`. The `useCryptoData` hook catches these specific status codes and provides a user-friendly "Cooldown" message instead of a generic error.

---

## 5. Persistence Layer
State persistence is implemented as a **Side Effect** within the hooks:
- **Mechanism**: `useEffect` listens to state changes and writes to `localStorage`.
- **Hydration**: State is initialized using a functional initializer: `useState(() => JSON.parse(localStorage.getItem(...)))`. This avoids reading from disk on every render.

---

## 6. CSS Architecture
- **Tailwind JIT**: All styles are utility-based, ensuring zero unused CSS in production.
- **Custom Animations**: Defined in `tailwind.config.js` and `index.css` for specialized interactions like `drawerSlide` (Portfolio) and `toastSlide`.
